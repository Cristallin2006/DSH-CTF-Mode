# CTF 模式

本入口要求已启用预设且 dsh_ctf 可见。普通会话若只手动读到此文件，不得声称强制加载/钩子准入已激活；可继续按专业 skill 分析，或按 docs/CTF-MODE.md 明确配置预设。

此正文由 CTF 预设宿主在模型调用前完整交付；无需重复调用 skill。收到题目后先核对完整题面、附件/实例、用户目标及现有约束，再主动使用 dsh_ctf select 选择模式与相关技能。不要等用户提醒加载。

## 主动选择

- 单题、耦合度高或下一步清楚，通常选择 `solo`：主会话直接使用已有工具分析和验证。
- 题库、多目标、可独立验证的工作包，或单题中确有值得分工的复杂部分，可选择 `orchestrated`：主会话负责计划、交接和复核，由持续型 Solver 执行。
- 单题不必然单兵，题库也可串行。说明当前选择的理由，考虑依赖、共享状态和交接成本；不按题数、关键词或固定尝试次数机械判断。
- 尊重用户明确偏好。运行上下文中的 preference 为 auto/solo/orchestrated，分别表达自动判断/优先单兵/优先编排，优先项可按任务证据合理调整；它不等于实际 mode。locked_mode 非空才是显式启动锁定。用户可通过 CTF 会话控件调整偏好或空闲时切换实际模式，核对当前状态后继续，不依据旧摘要声称仍在先前模式。

例：`dsh_ctf {action:"select",mode:"solo",reason:"本题先识别附件并验证单一路径",skill_plan:{required:[{name:"ctf-misc",reason:"附件格式和隐写线索"}]}}`。

纯计划、说明或非技术任务可显式声明 `required:[],none_reason:"为何此时不需要专业方法"`。这不移除本入口与 analysis-session 的基础材料。真正解题应按证据选至少一个相关专业 skill：Web→ctf-web；密码结构→ctf-crypto；原语/利用→pwn-exploit；未知二进制→re-triage；静态/动态按问题选 ghidra-static/re-dynamic；流量→traffic-analysis；杂项/附件→ctf-misc；跨主机链路→ctf-attack-chain。

所选正文及 skill 自带必读参考由宿主在下一模型步完整交付并记录摘要；材料过大或缺失时停止准入并说明原因。其他专题仍按需读取，不全量预载知识库，不把工具调用次数当理解或正确应用的证明。

## 两种工作方式

单兵可直接执行已经授权的实验；简单查询无需建立完整任务。多阶段任务按 analysis-session 记录目标代次、证据和未决前提。

选择编排后，宿主会再加载 analysis-orchestration。按该技能 init/bind → 打开记忆 → enable → 声明工作包的 skill_plan/execution_plan → dispatch → 监督/复核；选择模式本身不初始化任务或启动 Solver。主会话不要用 shell、其他派单入口绕过专职角色。Observer 保持零工具，Solver 仍由编排层独立交付其所需材料。

切换模式使用 dsh_ctf select。编排转单兵前先通过原编排接口停止并确认收尾、disable；模式工具不会暗中取消任务或关闭实例。重载插件后重新选择，不能凭旧的 loaded 标记假定当前材料仍可见。

## 证据和钩子

宿主核对本会话实际成功的启动/最近钩子回执；配置文件存在不等于钩子执行成功。故障时检查 analysis_session health，修复配置或状态后维护重载；不假装已持久化。

完整保留原题面与附件引用。候选、局部模型、自洽对拍、干预实验和原目标接受分别说明；未知可保留为未知。flag 形状不证明正确，提交成功以实际反馈为准。方法、重试和合理实验由模型根据证据选择，没有额外的固定时间盒、网络尝试额度或自动扩权。
