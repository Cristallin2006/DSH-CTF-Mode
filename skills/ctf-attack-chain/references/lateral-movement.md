# 跨主机与代理：链路证据和通道

从已授权主机的监听/已建立连接、路由、hosts、邻居和应用配置中生成端点候选；这些记录可能过期或含哈希，不代表相应主机当前可达。新端点是否在范围内由当前授权确定，不从“内网地址”自动推定。

```bash
ss -tlnp
ss -tnp
ip route
ip neigh
cat /etc/hosts
```

known_hosts、SSH key、数据库配置和应用服务账户可提供身份/主机线索；将凭据与具体服务关联，不对所有主机机械复用。哈希 known_hosts 可对已有候选用 `ssh-keygen -F HOST -f FILE` 检查，匹配不证明当前连接身份。

## 异常扫描结果

大量端口秒级全开、不同端口相同 banner 或相同 HTTP 页面，可能来自代理/WAF/通配服务，也可能确有统一服务。选少量代表端点，比较握手、协议交互、响应来源和目标侧监听/日志；标记未确认结果，不直接宣布扫描整体为假。

## 按证据选择通道

```bash
ssh -L 127.0.0.1:13306:INTERNAL_DB:3306 user@PIVOT
ssh -D 127.0.0.1:1080 user@PIVOT
ssh -J user1@HOP1,user2@HOP2 user3@FINAL
```

记录每跳身份、源/目标地址、绑定位置和代理协议。SOCKS 不自动代理所有工具/协议；经代理的 connect 探测与原始包扫描能力不同，按工具实际行为判断。隧道建立不证明最终应用接受，代理端成功也不等于内部服务成功。

已有代理、临时转发与新建通道按当前条件选择。变更和生命周期按宿主资源管理处理；不自动遍历整个子网或新增长期访问方式。
