# 凭据来源、验证与失败解释

从已有题面、附件、授权靶机配置/历史记录和目标应用材料中寻找账户、secret、私钥或会话线索；不要默认口令必然在某个字典里，也不要枚举与任务无关的本机个人文件或环境秘密。

## 来源与适用范围

- 配置：已定位应用的 .env、数据库配置、部署文件、备份和源码注释。
- 账户材料：目标环境的 .netrc、数据库客户端配置、SSH 私钥及已知主机记录。
- 题目提供的字典：主题、格式和已知账户相符时可优先作为候选；文件小或命名异常本身不是定制证明。
- 会话材料：Flask secret、JWT 密钥和 cookie 结构只是路线前提；签名算法、claims、有效期、服务及实际接受均须核对。

记录账户域、主机/服务、凭据来源和目标代次。直接登录、离线哈希检验与会话重建按已有证据选，不把一种方式规定为必经阶段。

## 认证实验

先用可解释的正负例或明确的失败观察核对工具判据、CSRF/cookie、重定向和错误响应，防止过滤串错误产生假阴性/假阳性。已授权的有限候选验证可使用相应工具，例如：

```bash
hydra -l USER -P scoped-candidates.txt ssh://TARGET -t 1
hydra -C scoped-userpass.txt ssh://TARGET -t 1
```

示例不设置通用请求许可或尝试额度。预算、速率、并发和锁定规则来自当前授权/目标条件；锁定、验证码和连接错误需要重新判断，不从“第 N 次尝试”或“未锁定”推断无限验证。验证码能否复用、响应是否区分用户都只在实际测试的会话/输入内报告。

## 离线哈希

识别格式后核对编码、salt、KDF 参数和输入来源；hashid 等给出候选，不能独立确定格式。按已确认的模式使用 john/hashcat，并将恢复值回到相应服务验证。零命中保留字典覆盖、账户身份、格式和环境等解释，不直接归因为字典太小或凭据不存在。
