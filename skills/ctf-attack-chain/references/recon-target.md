# 目标侦察：入口、路由与可区分观察

先阅读原始题面和已给附件，核对目标实例、入口、身份及范围。按线索选择页面/脚本、robots、sitemap、错误响应、已知备份路径、配置或版本材料；不强制所有入口逐一探测。

```bash
curl -i http://TARGET/robots.txt
curl -i http://TARGET/sitemap.xml
curl -i http://TARGET/KNOWN_PATH
```

HTML/JS 中的主机名、接口、注释与迁移提示可生成下一步假设。源码、构建配置和依赖清单能帮助确认版本；banner 与状态码单独不足以定案。某次报错带尝试计数不能证明没有锁定或可以高频验证。

需要目录发现时，先建立不存在路径的对照，记录状态码、重定向链、响应体及缓存/认证条件。与对照同码同大小只是 catch-all 候选，不能自动删除；真实页面也可能同长，响应还可能动态变化。按用户约束选择字典、并发与请求范围，而非从固定阈值推断路线错误。

```bash
ffuf -u http://TARGET/FUZZ -w scoped-paths.txt -t 1
```

重复试验没有区分新解释时，重新检查已给信息、请求身份、代理和路由，再选择有区分力的实验。报告实际探测的端点和未覆盖范围，不把局部未发现升级为全局不存在。异常端口响应见 lateral-movement.md。
