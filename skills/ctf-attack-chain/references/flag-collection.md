# 候选收集、分段关系与提交

根据题面和实际访问能力，在目标的应用文件、数据库、用户目录、服务响应、附件或环境材料中定位候选。路径名称和 flag 形状只是线索；不把每个匹配项自动当作有效答案。

每段保存原始字节/文本、主机与服务、路径/接口、获取命令、身份、目标实例和时间。保留换行/编码信息，不用摘要替代原文。来源是原目标输出、离线推导还是干预实验应分别标明。

分段关系依据题面、stage 标记、上下文或验证接口决定。段数、拼接顺序和分隔符未知时保留假设；来源位置本身不足以证明拼接顺序。接口支持分段验证时可按规则验证并记录实际反馈。

提交前核对格式、来源、目标代次和服务状态。提交失败可能涉及格式、过期实例、错误候选、身份或平台问题；先保存原证据并做有区分力的检查，不默认重启实例。重启可能生成新 flag 或破坏现有证据，须遵循当前生命周期约定。

成功以提交接口明确接受为准。未完成时交付已获取的段、各自出处、未证实的关系和下一步所缺条件；按需用 analysis-session 记录可继续的链路。
