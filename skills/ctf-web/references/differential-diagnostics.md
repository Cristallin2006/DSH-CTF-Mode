# 会话、框架入口与多服务差异诊断

## 会话改变后异常

对照干净客户端和原客户端，在相同目标代次、路由、请求方法和输入下比较携带/不携带相关 cookie 或 token 的结果。保留状态码、响应差异和时间，区分签名处理、身份语义、后续业务异常及传输失败。

无 cookie 恢复只支持异常与当前状态有关，不独立证明密钥正确、身份已接受或根因已定位。根路径正常也不能证明业务/评分路径健康。应用日志或源码仅在已有访问权限下核查；不为诊断自动重启、清库或重建环境。

## 疑似框架解码/反序列化入口

版本号、特定错误和 500 是线索。核对实际版本/构建、功能是否启用、输入解析链、攻击者可控字段、目标语义与可观察成功判据，再决定是否需要方法资料或最小本地模型。未能构造利用不能直接归因于“只缺 payload”；解析异常也不证明已具备任意代码执行条件。

知识资料的来源和版本需要可核对。按允许的资料获取方式补充，不为框架名字自动联网、下载 exploit 或提升工具权限。

## 多服务链路受阻

维护最小可达性与依赖关系：哪个入口从哪个网络视角可访问、已知服务和端口的证据、需要的身份或访问原语、当前不可达的前置条件。配置、页面提示、现有连接和已获准的服务发现可以补充图。

未知端口不等于不存在服务，也不证明未知端口一定是突破口。按当前线索、允许范围和请求成本决定发现范围；完整端口枚举仅在确有价值且获准时选择，不设为所有任务的第一步。不因链路阻塞扩大网段、复用无授权凭据或重置额度。

## 异常复现包

保存脱敏的有效/失败输入对、目标身份/代次、客户端与会话条件、时间、响应及有限重现结果；无法提供有效对照时明确说明。失败原因可保持未知。既有证据允许时再区分客户端、输入协议、业务处理、环境和平台故障，不自动发送申诉。
