# 登录受阻与有限候选实验

回查完整题目、附件、页面/JS/注释、公开配置与错误响应，区分“缺少必要输入”“认证假设错误”和“目标退化”。原文用可核对来源获取，不能只信子代理摘要。容器内配置只在已有入口与相应授权时检查，不把读不到的内部文件列为必须完成的前置步骤。

尝试候选前分别判断：是否获准、来源是否支持、成本是否值得、运行预算是否足够。派生不等于自动合法或有效，通用字典也不一概非法。同网段不代表允许跨题复用凭据。

已有材料支持的有限候选集合，可以在预算内分批完成，无需每批重新写理由。首次只保存一条简短实验记录：假设、候选来源/规则、去重范围与数量、目标代次、计量单位、预算引用/期限、成功判据和停止条件；后续只更新变化。可用 analysis_session record(kind=experiment)，不要逐请求记账或另建台账；记录本身不产生授权。

预定集合结束且没有新增依据时，不自动拼接更大的通用字典。失败只排除当前条件下的有效候选，不证明所有口令都不可猜。新材料或经验证的生成规则可以支持重估；仅换词表文件名、换 worker、换账号不构成新证据，也不重置共享额度。

flag 变化不能证明凭据随机；跨实例附件哈希相同也不能证明题目损坏。认证 oracle 只表明能识别结果，不证明正确口令属于某个候选空间。历史成功路径是线索，不是本实例事实。词表用途不匹配时先核对来源，不能仅凭文件名禁止有依据的实验。

线索形成访问循环时，标明当前不可达的依赖，比较其他可达线索、获准 hint 与其他任务的机会成本；不要求先读取尚无权限的内部文件，也不要求穷尽固定清单。认证拒绝与握手失败、超时、限流、错误目标分别记录；传输失败不算有效的口令否定。

记录最小请求基线，比较状态、内容、时间与会话条件。连接复用不代替限速，线程数不等于实际请求速率。服务异常或响应已无法判定时暂停并核对；已知有限集合中的正常失败不要求中断整个实验。受控任务只能使用 dsh_control；现有 async_fuzz.py 和任意网络脚本不属于受控执行器的自动覆盖范围。

普通会话需要后台访问具体目标时，先按 analysis-session 的 job_scope 绑定目标代次、共享环境和合理期限，再使用原生后台 bash/job_output。这个入口只负责登记、TTL 与取消，不提供 SSH/FTP 请求配额，也不自动覆盖脚本自行脱离管理器的进程。目标切换通过 analysis_session 更新；未确认旧任务停止时不释放槽位。

网络路径按目标选择，不全局清空代理。curl 与 Python 不一致时核对目标、代次和代理路径；只有明确直连的客户端才考虑 trust_env=False。连接拒绝或地址变化先记为服务/路由/生命周期异常，缺少平台证据不称“反制”。

hint 的收益按可能提供的信息、成本、剩余时间和替代实验评估；信息缺口也可能适合买 hint。主代理复核原材料和阻塞条件，不只依赖子代理自报。


缺少凭据、验证延迟较高而无新信息、候选集合结束或出现新来源时，比较“取得输入”与“继续验证”的成本。维护最小关系：可达来源 → 可提供的身份/配置线索 → 适用服务/条件 → 验证入口。来源按实际证据选择，不固定要求某数据库、压缩包或协议；未获访问的来源是依赖缺口，不强迫读取，也不跨目标广播凭据。

有限实验明确单位：不同候选数、实际验证次数和协议请求数可能不同；同候选重试仍可能消耗验证与请求额度。离线候选与在线验证分别处理。编排 execution_plan 的 limits 缺受控适配器时会阻塞该实验，不能通过删除真实限制继续发送；普通 shell 的脚本循环不因模型承诺而自动被计量。
