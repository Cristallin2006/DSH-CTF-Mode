# WAF、过滤器与白名单：解析差异诊断

用于 CTF、实验环境或明确授权的 HTTP 测试。目标是找出“检查者看到的值”和“最终消费者使用的值”之间的可验证差异，而不是对 403 页面喷洒 payload。通用观察与证据边界见 [核心观察卡](core-observations.md)。

## 1. 先定位拒绝发生在哪一层

状态码不是层名。保留一个合法请求和当前失败请求，核对目标代次、网络视角、会话、Host、路径、方法、Content-Type、响应头、重定向和正文。响应需脱敏，凭据用受保护引用。

| 观察 | 可提出的解释，不是单独结论 |
|---|---|
| 统一拦截页、网关头、规则 ID、连接在特定输入下中断 | 网关/WAF 或前置过滤器 |
| JSON 业务错误、登录后变化、同路径仅部分身份可访问 | 应用认证、授权或业务规则 |
| 同一输入在 GET 正常而 POST 被拒绝 | 方法路由、正文解析或方法级 ACL |
| 浏览器通过而脚本收到 JS/验证码挑战 | Bot/客户端挑战，不等于注入过滤 |
| 429、随请求量增加的延迟或连接失败 | 限流、服务退化或网络问题 |
| 仅特定关键字、编码或正文形式触发差异 | 输入检查与后续解析之间可能有差异 |

尽量用合法/异常输入、干净/原会话、浏览器/原始客户端等对照缩小层面。没有规则 ID 或源码时，可以只记录“疑似前置过滤”，不要虚构厂商和版本。`wafw00f` 等指纹结果仅作线索。

## 2. 建立可判定的最小实验

1. 固定一个已知入口和成功判据，先证明正常输入能到达预期业务分支。
2. 用一个最小异常输入确认“被拒绝”和“到达后无效果”能够区分；保存原始请求与响应摘要。
3. 每轮只改变一个维度。建议顺序：表示/编码 → 路径/方法 → 参数/媒体类型 → 代理与协议；有源码或明确指纹时可直接选对应维度。
4. 每个变体都回答一个问题，例如“后端是否解码两次”“代理是否保留编码斜杠”“应用是否只读取第一个参数”。无法区分解释的变体不进入批量阶段。
5. 命中后回到原始客户端重放最小有效对，并验证真实原语：预期数据、内部端点响应、受控状态变化或题目接受。只有 200、长度变化、反射、挑战页消失或状态码从 403 变成 500，不算绕过成功。

记录：`变量 / 检查层假设 / 最终消费者 / 对照结果 / 语义验证 / 适用范围`。同条件负结果只排除该输入与当前条件，不排除整个技术族。

## 3. 按证据选择差异面

### 表示、编码与规范化

- URL 百分号编码、重复编码、大小写、Unicode 规范化、字符集和 HTML/XML 实体，只在对应消费者确实执行转换时测试。
- 区分“传输编码”“应用解码”“浏览器规范化”“数据库/模板语法”发生的顺序；重复编码不是默认技巧，需要两重解码证据。
- 对黑名单删除、单次替换和大小写规则，构造能揭示转换后值的最小回显或本地模型。不要把语法有效但未触发目标的变体当成突破。
- 畸形 UTF-8、NUL、CRLF、超长输入和正则资源耗尽可能造成拒绝服务或不可知结果，不作为普通首批实验；只在隔离副本、明确边界和可恢复条件下检验。

### 路径、路由与方法

- 有代理/框架链证据时，逐个检验尾斜杠、重复斜杠、点段、分号参数、编码路径分隔符、大小写、反斜杠和尾点后缀；一次只改一处。
- 比较网关原始路径与应用路由值。`OPTIONS`/`Allow`、错误页和源码可帮助确认方法路由；方法变化只用于只读或已授权操作，不自动尝试写方法。
- `X-Original-URL`、`X-Rewrite-URL`、Forwarded/Host 类头只有在中间件确实消费时才有意义。先找配置、源码或响应证据，避免组合喷洒。
- 403 消失后还需证明命中的是同一业务处理函数，而非静态页、catch-all、错误处理器或另一个虚拟主机。

### 参数、正文与解析器

- 对重复参数分别测试单值顺序和表示差异，并通过回显、源码或框架实测确认应用取首值、末值、拼接还是数组；不要套用固定“某框架总是如此”的表。
- 仅在应用支持另一种表示时比较 form、JSON、multipart、XML 或文本正文。保持业务字段和值不变，才能归因于 Content-Type/解析差异。
- JSON 注意重复键、数字/字符串类型、嵌套与 Unicode 转义；XML 注意实体解码；multipart 注意字段名、文件字段和边界解析。深层嵌套、超大正文及畸形分块传输不属于默认测试。
- SQL、模板和命令过滤的具体语法变异进入对应专题；本卡只负责定位差异和验证语义，不用 `sqlmap --tamper` 列表代替模型。

### 代理、协议与客户端信任

- 只有证据表明应用信任代理提供来源地址时，才单个比较 `X-Forwarded-For`、`X-Real-IP` 或标准 `Forwarded` 的处理；不假定伪造头能改变真实网络来源。
- HTTP/1.1 与 HTTP/2、绝对形式 URI、分块编码及请求走私具有链路和副作用风险。已有前端/后端解析证据且在隔离或明确许可范围时才测试；不把它们作为 403 的通用下一步。
- Bot 挑战与 WAF 分开处理。真实浏览器重放可验证客户端假设，但不自动规避验证码、访问控制或平台限制。

## 4. 白名单按“最终消费者”分类

### URL / SSRF

画出 `原始 URL → 校验器解析 → 规范化 → DNS 解析 → 重定向 → 实际请求`。分别确认 scheme、userinfo、host、port、path 和 IP 的检查值与使用值。解析差异、十进制/十六进制 IP、IPv6、DNS 变化与重定向只在已有对应数据流时进入实验；具体方法见 `../server-side.md` 和 `../server-side-advanced*.md`。不要因字符串包含可信域名就认定校验通过或请求到达内部服务。

### 路径与访问控制

区分网关 ACL、框架路由、文件系统规范化和业务授权。白名单可能只覆盖前缀、扩展名或特定方法；用最小路径对照验证匹配边界，不把 200 的默认页当成受保护内容。已有路由判例见 `../auth-and-access.md`。

### IP、代理与内网信任

确认可信代理层数、实际读取的头字段以及应用看到的是直连地址还是转发地址。内网地址字面量被接受不等于获得内部身份；必须观察受保护业务结果。不要通过更换出口、分布式请求或扩大网段绕过限制。

### CSP、跳转与可信域

列出允许源、重定向每一跳和浏览器最终解析结果，区分 host 后缀匹配、公共后缀、用户可控子域、JSONP/回调与脚本 MIME。CSP 通过不等于脚本执行，脚本加载也不等于完成数据读取；使用无损害标记验证。专题见 `../client-side-advanced.md` 与 `../auth-infra.md`。

### SQL、命令、模板与通用字符串过滤器

确定过滤发生在拼接/调用之前还是之后，是拒绝、删除、转义还是规范化；识别是否只执行一次。先用本地函数或无害回显恢复转换函数，再选语法等价形式。禁止词消失不等于最终语义存在，最终语义存在也要回到原目标验证。按入口进入 `../sql-injection.md`、`../server-side-2.md` 或 `../server-side-exec.md`。

## 5. 请求成本与停止条件

- 首批只跑能区分当前假设的少量变体；命中新指纹、源码或解析证据后再回溯旧负结果。
- 429、连续 5xx、超时增加或目标退化时暂停并检查速率、会话和实例健康，不自动重放积压请求。
- 无新增证据时停止扩字典和组合变异，重新检查入口、身份、数据流与成功判据。请求数量不是覆盖率。
- 普通 shell、浏览器和 MCP 不自动继承任务预算；需要硬限制时使用 `analysis-session` 的受控请求能力并先核对实际状态，不能声称文本约定形成了机械门。
- 对目标不明确的直连源站、绕过平台封禁、IP 轮换、分布式请求和拒绝服务型变异，不因本卡获得授权。

```text
命中的最小有效对：
后端语义与目标接受验证：
未区分解释 / 下一步证据：
请求预算、会话与副作用：
```
