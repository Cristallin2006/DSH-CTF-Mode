# 密码分析：对象、前提与验证

用于选择数学方法和解释结果，不要求遍历所有攻击。

## 对象与条件

区分原始观察、推断和未知值；保留参数来源、模数/域/群、位长、取值范围、编码及 oracle 的实际语义。看到 RSA、ECC、AES 或格结构不代表具体攻击条件已经成立。因子位长不等于模数位长；有限精度近似、泄漏的高/低位、nonce 复用和噪声界不能互相替代。

数学结构尚未从二进制恢复时，先由静态/动态分析提供语义；已经明确数学对象则可直接建模。缺少某个实现后端只说明该执行路径受阻，不说明数学方法不可行，也不自动授权安装大环境。

## 字节与算法接口

整数转字节核对端序、固定宽度、前导零、符号、分块和 padding。文本与原始字节分开：非可打印结果可能合法，字母数字外观也不能证明是答案。

Base64 的 alphabet 与填充规则来自目标协议；标准有填充、URL 字母表和允许省略填充的变体不能混用。格式不匹配首先只证明当前输入不满足已声明格式，不能直接归因读数错误。XOR/RC4 的纯变换等长，但包含 IV、头部、编码或切片的外层格式可能不等长。

## 独立检查与负结果

用原关系核对候选，例如因子乘积、模运算、签名关系或已知输入输出；再核对实际字节接口。工具返回非空、同一脚本加解密往返、某个前缀匹配均不单独证明目标接受。

`None`、预算中断、后端缺失、攻击前提不满足和覆盖完整的有限空间无解分别记录。增加格维数或扩大枚举应有新增依据，工具无命中不能排除所有方法。没有可靠目标验证时保留 candidate/tested 的范围。

具体攻击接口见 [攻击条件与独立检查](crypto-attack-contracts.md)；按实际结构选择主文的 RSA、ECC、格、PRNG 等专题，避免因算法名命中就加载整套配方。
